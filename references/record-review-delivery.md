# 原始数据识别与用户核对的交付方式

用户需要核对手写实验记录识别结果时执行本模块。

识别本技能所有者的记录时，同时读取[个人记录习惯](user-record-conventions.md)；其他用户未确认的习惯不自动套用。

## 1. 交付文件

| 文件 | 用户如何使用 | 内容要求 |
| --- | --- | --- |
| `实验原始数据记录表.md` | 直接核对、修改数字和量程 | 按原表逐格转写，保留列序、空格、划改和补写位置 |
| `实验原始记录_核对版.pdf` | 查看整页表格、打印核对 | 与 Markdown 内容一致，保留表格网格，关键字迹附局部原图 |
| `原始记录照片/` | 回到完整原页查证 | 原图不覆盖、不改字迹，固定图片编号并保留原文件名对应关系 |
| `识别疑点清单.md` | 集中处理少量无法确定的内容 | 逐项说明照片、表、行列、候选读法及局部图；没有疑点时不必单独建立 |
| 转录 JSON 或同等结构化源文件、PDF 生成脚本 | 复现核对版、追溯单元格来源 | 放在项目内，交付时给出准确路径，不要求用户手工同步多个文件 |

用户主要编辑 Markdown；PDF 提供版面核对。结构化数据和代码在后台维护，不能让用户分别修改三份内容。

## 2. 原样转写规则

1. 保留原表名称、表头、单位、列序和各组测量顺序。只省去完全未填写且无批注的测量行；有数字、划改、备注或独立补记的行全部保留。
2. 保留下来的行中，未填写的单元格仍为空白。不能为了“表格完整”自动补零、补量程、补重复值或移除空列。
3. 保留原始正负号、小数位、量程、区间及有辨读意义的末尾点号。计算时需要的格式规范化另行进行。
4. 划去的旧值与替换值同时呈现，例如 `~~35~~ 36.0`。被遮盖的旧字迹无法还原时，不编造旧值；附原图裁切。
5. 补写在表头、边缘、空行或表格外的内容保留位置关系。例如表头下沿补写的量程应在表头对应位置呈现，不能未经确认移入某一数据行。
6. 表格下方的加测数据单独列成小表，注明原位置。不能并入主表后让用户误以为它原本属于主表。
7. 用 `□`、`[叠写]` 或脚注标记不能确定的字符，并明确这些是转写标记，原纸上没有。候选读法不作为已确认的计算输入。

“原样”要求测量信息、填写状态和修改关系对应；字体与线宽可作清晰、简洁的排版处理。

## 3. 核对 PDF 的页面组织

默认采用 A4 横向，适合宽记录表；优先一张原记录对应一页。内容过多时允许续页，重复表头并保留原页编号，不能强行缩小到难以辨读。

每页按以下顺序组织：

```text
实验名称／本页测量项目                 原记录页码／核对页码

原样转写表格
  原列名、原列序、已填写行、空白格、划去旧值及补写新值

表格外加测或补记的小表（如有）

少量辨读说明
  只解释不清楚的字迹、划改位置或未确定的作用范围

关键局部原图＋图注
  叠写、划改、倍率、补写或易混淆数字的裁切

转写符号说明与页码
```

- 使用黑白文字、清楚的表格网格和适当留白，不加入装饰底纹或彩色区块。
- 局部图直接来自原图，保持比例，保留足够的表头、行列或相邻字迹，便于定位。
- 表头字号、行高和裁切大小以手写数字、指数及划改能看清为准。
- 完整原图在 Markdown 中链接或展示；局部图不能替代完整原页。
- 独立核对 PDF 的横向版式不自动套用到正式报告。正式报告的照片附录页面应与正文统一。

## 4. 空白格沿用与原样展示

本用户已确认：同一表、同一列中，后续空白格表示沿用前一个已填写值；明确填写的新值更新该条件，不跨独立表沿用。整列未填且表头及适用说明也没有来源时，保持“未记录”。仅有视觉分组或分隔行不能擅自改变这条约定。

单位、量程及其他必要信息省略重复填写时，也按“同上”处理。来源可以是本表表头、同列前项或明确适用的说明，不能只因当前格未写就认定缺失。整列空白但表头已给单位时，单位仍然已知；只有所有适用来源均无记录时才标为未记录或待确认。

核对版仍展示原有空白。用于计算的数据可展开沿用值，并保留“来自哪一行”的来源信息。其他用户没有明确这一习惯时，不自动套用。

## 5. 核对与更正流程

1. 保存完整原图并编号，逐张查看整页，确认主表、表格外数据和批注均已覆盖。
2. 完成逐格转写，对含划改或不清楚的内容保存局部图。
3. 由同一转录来源生成 Markdown 与核对 PDF，检查二者的数字、量程、空白和修改关系一致。
4. 交付两个主要文件，明确告知用户可以直接在 Markdown 中修改，并只列出尚待确认的具体位置。
5. 用户核对后的文件及其最新明确更正成为权威来源。生成器不得用旧 JSON、旧 CSV 或旧回复覆盖用户编辑的表格。
6. 更正必须定位到“照片／表名／电压或序号／列”。主表和加测表即使使用同一波长，也必须按具体行列分别定位，不能连带修改。
7. 修改后保留必要的历史快照或更正记录，重新生成受影响的数据与 PDF。进入报告分析阶段时，再同步计算、曲线及相关结论。

理论趋势和数量级检查可以帮助发现疑点，但不能单独决定原字迹的读法。未经用户确认，不以“这样更合理”为由改写记录。

## 6. 交付前检查

- 每张照片均有对应记录；主表、加测、补记及修改全部覆盖。
- 按原图核对表数、填写行数、列数与原始示数，而非只检查最后结果。
- Markdown 和 PDF 内容一致；空白格没有被展示层自动补填。
- 删除线、上下标、正负号、量程和区间在 PDF 中正确显示。
- 裁切没有改变字迹，能定位到原图；不靠模糊字迹推造旧值。
- 逐页渲染查看，确认网格、表头、数字、说明和局部图清晰，无裁切或重叠。
- 用户已经核对的文件不会被历史生成脚本覆盖。

完成这些检查后，交付简短说明：两个主要文件的位置、用户的修改入口、少量待确认项，以及结构化源文件和生成脚本的位置。核对阶段的识别说明留在核对材料中，不进入正式实验报告正文。
